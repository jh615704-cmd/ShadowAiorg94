---
name: Trade contract selection
description: Exact-barrier semantics and settlement display rules for digit trading features.
---

For Digit Differs, the selected digit is the barrier that must not be the final digit at expiry; intermediate ticks do not settle the contract. Manual taps must submit that exact barrier, while ranked automation may choose a candidate only when it is explicitly surfaced as ranked mode. Trade X observation windows must use the next live ticks, not ranked-history positions. Clock Work contracts always last five ticks; Start chooses the best eligible Higher/Lower barrier using the selected win-rate threshold even when the Ai Clock switch is off. Keep this selection logic behind Start, score with available market history, and require one fresh quote to confirm an entry. Bulk Trader sends the selected 1–5 post-entry ticks unchanged for Over, Under, and Differs; tick 0 is the entry spot, and Deriv's sold/settled update is authoritative.

For grouped multi-contract actions (Auto Trader, Bulk Trader, Clock Work, Matches, Dual, and Jackpot), quote every leg first and dispatch the buys together to avoid artificial per-contract delays. Jackpot's 1–9 batch count means complete dual pairs, each with one Rise/Fall contract and one Even/Odd contract, for 2–18 contracts total. Each contract still has its own Deriv acknowledgement, entry quote, and settlement; never promise identical outcomes or an exact shared entry tick. Preserve confirmed contract IDs when only part of a batch is confirmed, and require account-history review before any uncertain order is resubmitted. Features that intentionally wait for settlement before their next entry remain sequential. For Jackpot, the user confirmed that this settlement protection should stay instead of allowing overlapping batches; its Place button should unlock automatically after settlement is confirmed.

**Why:** Duration-based ranked selection previously replaced a digit the user had selected, and open-contract mark-to-market profit was displayed as a loss before settlement. An artificial delay between already-quoted legs also caused grouped entries to start at different market ticks. Waiting for six new quotes to form one five-tick outcome delays Clock Work even when recent market history is already available. A quote can move while a buy request is pending, so users may see more than one digit after pressing Buy even though the configured contract duration is exact. The user wants Clock Work Start to run selection without requiring the Ai Clock switch, does not want explanatory copy about the hidden selection logic in the panel, clarified that Jackpot's batch count is complete pairs, and explicitly chose to retain Jackpot's settlement guard rather than permit overlapping batches.

**How to apply:** Keep manual and automated entry selection explicit, observe the configured number of fresh ticks before Smart Auto evaluates, and never use an automation setting as the contract duration by accident. For Bulk Trader, send the chosen 1–5 duration in both proposal and buy parameters; keep the one-tick post-entry expiry semantics in order logic without displaying the entry-quote/tick-0 explanation, and never synthesize a local settlement from a visible digit. Keep Clock Work fixed at five ticks; pressing Start must run the selected threshold check and barrier choice regardless of the Ai Clock switch, without adding explanatory algorithm copy to Clock Work. Confirm each new entry on one fresh quote; if history or a qualifying setup is unavailable, wait rather than guess. Block overlapping contracts when the feature expects sequential settlement, and display profit only after the contract is closed. For Jackpot, keep the account-wide settlement guard and uncertain-order review, keep the Place button disabled while Deriv reports open contracts, show the user why it is waiting, and allow it to unlock automatically after the confirmed settlement and result sync. Compute exposure as twice the complete-pair count times the per-contract stake. For grouped batches, dispatch the already-quoted legs together while preserving per-leg acknowledgements; a rejected or uncertain leg must not hide confirmed siblings or trigger an automatic replay.
